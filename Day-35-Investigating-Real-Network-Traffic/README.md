Lesson of the Day

Today, I focused on investigating real network traffic using Wireshark.

A good investigation is not about looking at every packet individually—it's about asking the right questions, filtering the relevant traffic, and documenting the findings.

Analyst Investigation Workflow

Today's lesson introduced a six-step workflow commonly used during network traffic analysis.

1. Orient First

Before searching for suspicious activity, understand what is inside the packet capture.

This includes identifying:

Which protocols are present
Which devices are communicating
The overall size of the capture
General traffic patterns

Starting with an overview makes later analysis much easier.

2. Form a Question

Rather than examining packets randomly, begin with a specific question.

Examples include:

Is there unusual DNS traffic?
Which device generated the most traffic?
Are there unexpected connections?
Is there suspicious communication?

A clear question helps focus the investigation.

3. Filter the Traffic

Use Wireshark display filters to isolate only the packets relevant to the investigation.

Examples include filtering by:

Protocol
IP address
Port
Specific conversations

Filtering removes unnecessary information and speeds up analysis.

4. Follow and Read

After identifying interesting traffic, follow the conversation between devices.

This helps analysts understand:

The sequence of communication
Requests and responses
Connection behavior
Packet flow

Reading traffic in context provides a much clearer understanding than viewing isolated packets.

5. Compare to Normal

An important part of analysis is comparing current traffic with expected or normal behavior.

Questions to consider include:

Is the traffic typical?
Is there unexpected communication?
Are packet sizes or frequencies unusual?
Are unfamiliar protocols being used?

Comparing against normal behavior helps identify anomalies.

6. Document Findings

Every investigation should end with proper documentation.

Analysts record:

Observations
Evidence
Screenshots (if needed)
Conclusions
Recommendations

Clear documentation allows others to understand and verify the investigation.

Wireshark Orientation Tools

Today's lesson also covered several built-in tools that help analysts quickly understand a packet capture.

1. Statistics Menu

The Statistics menu provides an overview of captured traffic and summarizes important network information.

2. Protocol Hierarchy

The Protocol Hierarchy shows all protocols present in the capture and the percentage of traffic generated by each protocol.

This helps identify which protocols dominate the network communication.

3. Conversations

The Conversations view displays communication between different devices.

It helps identify:

Active hosts
Communication partners
Packet counts
Data transferred
4. Endpoints

The Endpoints view lists all devices involved in the packet capture.

It provides information such as:

IP addresses
MAC addresses
Packet counts
Bytes transmitted
5. I/O Graph

The I/O Graph visualizes network traffic over time.

It helps analysts identify:

Traffic spikes
Unusual activity
Changes in communication patterns

Graphs often make trends easier to understand than raw packet data.
