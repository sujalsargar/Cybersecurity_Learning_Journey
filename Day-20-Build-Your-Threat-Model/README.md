Day 20 - Build Your Threat Model
Objective

Apply everything learned during the first 19 days of my cybersecurity journey to create a structured Personal Threat Model.

Today was not focused on learning a completely new technical concept. Instead, it was a project day where I used my previous knowledge about data, passwords, phishing, networks, web security, mobile devices, cloud security, attack processes, and social engineering to analyze my own digital risk.

Lesson of the Day

Today, I learned how to bring multiple cybersecurity concepts together into one structured document:

A Threat Model

A threat model is a structured document that answers four important questions about a specific person, system, application, or organization.

The Four Questions of Threat Modeling
1. What Am I Trying to Protect?

This question identifies the assets.

Assets are anything valuable that could be:

Stolen
Exposed
Modified
Destroyed
Misused
Made unavailable

Examples include:

Email accounts
Social media accounts
Banking accounts
Personal documents
Photos and videos
Source code
Cloud accounts
Mobile devices
Laptops
Password manager data

The first step in security is understanding what actually needs protection.

2. Who Would Want to Attack It, and Why?

This question identifies the threat actors.

Different attackers have different motivations.

Possible threat actors may include:

Cybercriminals
Scammers
Phishing attackers
Credential thieves
Opportunistic attackers
Malicious insiders
Advanced threat actors

Possible motivations include:

Financial gain
Identity theft
Account takeover
Data theft
Fraud
Espionage
Extortion
Reputation damage

Understanding the attacker helps make the threat model more realistic.

3. How Would They Actually Attack?

This question identifies possible attack scenarios.

Instead of thinking only about general threats, I learned to imagine realistic attack paths.

Examples include:

Phishing email
Credential stuffing
Password spraying
Smishing
Malicious applications
Social engineering
Session theft
Public Wi-Fi attacks
Cloud misconfiguration
Stolen device
DNS manipulation

The goal is to understand:

How could an attacker realistically reach the asset?

4. What Can I Do About It?

This question identifies:

Defences
Security controls
Priorities
Improvements

Possible defences include:

Multi-Factor Authentication
Unique passwords
Password managers
Software updates
Secure router configuration
Backup strategies
Device encryption
Phishing awareness
Reduced public information exposure
Cloud permission reviews
Logging and monitoring

The goal is not only to identify threats.

The goal is to decide:

What should I fix first?

Project Day

Today was a practical project day.

I used knowledge from the previous 19 days of my cybersecurity journey to create my own:

Personal Threat Model Report

This project helped me connect multiple cybersecurity topics instead of studying them separately.

Task 1 - Asset Inventory

The first task was to identify everything valuable that I need to protect.

I reviewed assets such as:

Personal accounts
Email accounts
Financial accounts
Social media
Devices
Personal data
Credentials
Cloud services
Development accounts
Source code and projects

The goal was to understand:

What would actually matter if it were stolen, exposed, modified, or lost?

Why Asset Inventory Matters

Security cannot protect everything equally.

Some assets are more important than others.

For example:

Primary Email Account
        ↓
Password Reset Access
        ↓
Other Accounts
        ↓
Potential Account Takeover

This helped me understand that one important account may provide access to many other accounts.

Task 2 - Threat Actors

The second task was to identify who might target my assets.

I considered possible threat actors such as:

Cybercriminals
Scammers
Credential thieves
Phishing attackers
Opportunistic attackers
Malicious insiders

For each threat actor, I considered:

What do they want?
Why would they target me?
Which assets would interest them?
What capabilities might they have?
Task 3 - Attack Scenarios

The third task was to create realistic attack scenarios.

Instead of simply writing:

"Someone may hack my account."

I learned to think in a more structured way:

Attacker obtains leaked credentials
        ↓
Attempts credential stuffing
        ↓
Password reused on another account
        ↓
Account access gained
        ↓
Sensitive information exposed

Another example:

Attacker researches public information
        ↓
Creates convincing internship message
        ↓
Sends phishing email
        ↓
Victim enters credentials
        ↓
Account takeover attempted

This task connected directly with previous lessons on:

Phishing
Password attacks
Social engineering
Data breaches
Cyber Kill Chain
MITRE ATT&CK
Task 4 - Defence Map

The fourth task was to map security controls against identified threats.

Examples:

Threat	Possible Defence
Credential Stuffing	Unique Passwords + MFA
Phishing	Verify Links + 2FA
Device Theft	Screen Lock + Encryption
Malicious Apps	Trusted Sources + Permission Review
Public Wi-Fi Threats	HTTPS + Avoid Unknown Networks
Router Compromise	Strong Admin Password + Firmware Updates
Cloud Account Attack	MFA + Least Privilege
Data Loss	Secure Backups

This helped me understand that security controls should connect to actual risks.

Task 5 - Priority Matrix and 90-Day Plan

The final task was to prioritize the identified risks.

Not every security problem has the same importance.

I considered factors such as:

Likelihood
Impact
Urgency
Difficulty of remediation

A simple priority model:

High Likelihood + High Impact
        ↓
Highest Priority
Low Likelihood + Low Impact
        ↓
Lower Priority

After identifying priorities, I created a 90-day security improvement plan.

The goal was to turn the threat model into practical action.

What I Learned
A threat model connects assets, attackers, attack scenarios, and defences.
Security should begin by identifying what actually needs protection.
Different threat actors have different motivations.
Attack scenarios should be realistic and specific.
Security controls should map directly to actual risks.
Not every risk has the same priority.
A threat model should lead to practical security improvements.
Previous cybersecurity concepts become more valuable when connected together.
Key Takeaways

✅ Identify assets before thinking about security controls.

✅ Understand who might attack and why.

✅ Create realistic attack scenarios.

✅ Map defences directly to threats.

✅ Prioritize based on likelihood and impact.

✅ Turn findings into an actionable improvement plan.

✅ Threat modeling helps move from reactive security to structured security thinking.

Reflection

Today was one of the most valuable days of my 90-day cybersecurity journey because I used everything I had learned during the previous 19 days to create something practical.

Instead of studying passwords, phishing, networks, mobile security, cloud security, and social engineering as separate topics, I connected them inside one personal threat model.

Creating my Personal Threat Model Report helped me understand that cybersecurity is not about applying every possible security control.

It is about understanding:

What matters
Who might target it
How they might attack
What should be fixed first

My biggest takeaway is:

Good security starts by understanding what you are protecting, who might attack it, how they would attack, and what you should prioritize first.
