Day 38 - Understanding Logs
Objective

Understand what logs are, explore different types of logs, learn what makes logs valuable during investigations, and practice reading log entries from a security analyst's perspective.

Lesson of the Day

Today, I learned about Logs, one of the most important sources of information in cybersecurity.

Every action performed on a computer, server, application, or network can generate a log entry. These records help administrators and security analysts understand what happened, when it happened, and who was involved.

A simple way to remember it is:

Logs are the recorded history of events that happen in a system.

Without logs, investigating security incidents would be extremely difficult.

What are Logs?

A log is a record of an event that occurred within a system.

Logs help answer important questions such as:

Who performed the action?
What happened?
When did it happen?
Where did it happen?
What was the outcome?

Logs are essential for:

Security monitoring
Troubleshooting
Incident response
Digital forensics
Compliance and auditing
Types of Logs

Today's lesson introduced several common types of logs used in cybersecurity.

1. Authentication Logs

Authentication logs record login and logout activities.

Examples include:

Successful logins
Failed login attempts
Password changes
Multi-Factor Authentication (MFA) events

These logs are useful for detecting unauthorized access attempts.

2. Network Logs

Network logs record communication between devices.

They may include:

Source IP address
Destination IP address
Ports
Protocols
Connection status

These logs help identify suspicious network activity.

3. System / Event Logs

System logs record operating system events such as:

System startup and shutdown
Hardware events
Driver issues
Service failures
Operating system errors

These logs are useful for troubleshooting and system monitoring.

4. Application Logs

Application logs record events generated by software applications.

Examples include:

User actions
Application errors
Database connections
API requests
Service activity

These logs help developers and analysts understand application behavior.

5. Audit Logs

Audit logs record security-sensitive activities.

Examples include:

File access
Permission changes
Administrative actions
Policy modifications
Configuration changes

Audit logs help organizations maintain accountability and support compliance requirements.

What Makes Logs Useful?

Simply collecting logs is not enough.

Today's lesson covered several characteristics that make logs valuable during investigations.

1. Accurate Timestamps

Every log entry should record the exact time an event occurred.

Accurate timestamps make it possible to reconstruct an incident timeline.

2. Synchronized Clocks

All systems should use the same time.

If different systems have different clocks, investigations become confusing.

3. Network Time Protocol (NTP)

Network Time Protocol (NTP) synchronizes system clocks across devices.

Using NTP helps ensure timestamps remain consistent throughout the network.

4. Enough Detail

Useful logs should contain enough information to understand the event.

Important details often include:

User
Device
IP address
Action performed
Result
5. Retention

Organizations should retain logs for an appropriate period.

Historical logs are often required for:

Investigations
Compliance
Audits
Threat hunting
6. Integrity

Logs must remain trustworthy.

Security controls should protect logs from unauthorized modification or deletion.

7. Centralized Logging

Instead of storing logs on individual systems, organizations often send them to a central location.

Centralized logging simplifies:

Monitoring
Searching
Investigations
Long-term storage
8. SIEM Benefits

Centralized logs become even more valuable when combined with a Security Information and Event Management (SIEM) platform.

A SIEM can:

Collect logs
Normalize data
Correlate related events
Generate alerts
Support investigations
Reading a Log Entry

A log entry is one individual record describing a single event.

Each entry usually contains technical information about something that happened.

A security analyst's job is to translate these technical details into a clear understanding of the event.

Common Information in Log Entries

Most logs answer five important questions:

Who performed the action?
When did it happen?
What happened?
Where did it happen?
What was the outcome?

Answering these questions helps build a complete picture of an event.

Reading Logs Like an Analyst

One important lesson today was learning to translate technical log entries into plain language.

Instead of simply reading raw data, analysts interpret the information and determine:

What happened?
Is the activity normal?
Does it require investigation?
Is it related to other events?

This process turns raw logs into meaningful security insights.

Investigation Workflow

Today's lesson reinforced a structured investigation process.

Orient – Understand the available logs and environment.
Question – Decide what you are investigating.
Filter – Search for relevant events.
Read – Interpret the log entries carefully.
Conclude – Determine what happened.
SIEM – Correlate logs from multiple systems.
Command Line – Use command-line tools to search and analyze logs efficiently.

Following this workflow helps analysts perform consistent and effective investigations.
