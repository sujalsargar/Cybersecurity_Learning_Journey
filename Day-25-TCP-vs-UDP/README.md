Day 25 - TCP vs UDP
Objective

Understand the differences between TCP and UDP, learn how they are used in modern networking, and perform hands-on packet analysis using Wireshark.

Lesson of the Day

Today, I learned about two of the most important transport layer protocols:

TCP (Transmission Control Protocol)
UDP (User Datagram Protocol)

Although both protocols are used to send data across networks, they are designed for different purposes.

A simple way to remember them is:

TCP is careful, ordered, and reliable.
UDP is fast, lightweight, and does not guarantee delivery.

Choosing between TCP and UDP depends on whether reliability or speed is more important.

TCP (Transmission Control Protocol)

TCP is designed for reliable communication.

Before sending data, TCP establishes a connection between the sender and receiver.

It makes sure that:

Data arrives successfully.
Packets arrive in the correct order.
Missing packets are retransmitted.
Duplicate packets are handled correctly.

If something is lost during transmission, TCP requests that it be sent again.

This makes TCP ideal for applications where accuracy is more important than speed.

The Three-Way Handshake

A TCP connection begins with the Three-Way Handshake.

Client              Server

SYN  ------------->

     <------------- SYN-ACK

ACK  ------------->

Connection Established

This process confirms that both devices are ready to communicate.

History of TCP

TCP was developed during the 1970s by Vint Cerf and Bob Kahn while working on networking research funded by DARPA.

Their work became one of the foundations of the modern internet.

Common Protocols That Use TCP

Many applications require reliable communication, including:

HTTP
HTTPS
SSH
SMTP
IMAP
IMAPS
FTP / SFTP
MySQL
PostgreSQL
Microsoft SQL Server (MSSQL)

Protocols that rely on TLS encryption also generally use TCP because encrypted communication requires reliable delivery.

UDP (User Datagram Protocol)

UDP is designed for speed and efficiency.

Unlike TCP, UDP:

Does not establish a connection first.
Does not guarantee packet delivery.
Does not guarantee packet order.
Does not retransmit lost packets.

Instead, packets are simply sent to the destination.

If some packets are lost, the communication continues without waiting.

This makes UDP useful for applications where speed is more important than perfect reliability.

Characteristics of UDP
No handshake
No sequence numbers
No acknowledgements
Lower overhead
Faster communication
History of UDP

UDP was introduced in 1980, approximately two years after TCP.

It was created to support applications that required low latency rather than guaranteed delivery.

Common Protocols That Use UDP

Examples include:

DNS
DHCP
NTP (Network Time Protocol)
Voice over IP (VoIP)
Video conferencing
Online gaming
Streaming applications

These services often prefer speed over retransmitting lost packets.

TCP vs UDP
Feature	TCP	UDP
Connection	Connection-oriented	Connectionless
Handshake	Yes	No
Reliability	Guaranteed delivery	Best effort
Packet Order	Maintained	Not guaranteed
Retransmission	Yes	No
Speed	Slower	Faster
Typical Use	Web browsing, Email, SSH, Databases	DNS, Voice Calls, Gaming, Streaming

What I Learned
TCP provides reliable and ordered communication.

Key Takeaways

✅ TCP is reliable and connection-oriented.

✅ UDP is fast and connectionless.

✅ TCP uses the Three-Way Handshake.

✅ UDP does not use acknowledgements or retransmissions.

✅ Web browsing, databases, and SSH commonly use TCP.

✅ DNS, DHCP, NTP, and voice communication commonly use UDP.

✅ Wireshark is a powerful tool for observing real network traffic.

Reflection

Today's lesson helped me understand why the internet uses both TCP and UDP instead of relying on a single protocol.

TCP ensures reliable communication for applications where every piece of data matters, while UDP allows faster communication for services such as voice calls and DNS queries where low latency is more important.

Using Wireshark made this lesson even more valuable because I was able to observe live network traffic instead of only reading about these protocols. Seeing TCP, UDP, DNS, HTTPS, and QUIC packets in real time helped me connect theory with practical networking.

My biggest takeaway is:

The choice between TCP and UDP depends on the application's needs—whether reliability or speed is the priority.
