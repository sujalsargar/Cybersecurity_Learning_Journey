Project Overview

Today's objective was to perform a basic security assessment of Maya's network.

The assessment involved:

Understanding the network environment.
Identifying valuable assets.
Finding potential security risks.
Prioritizing the most critical risks.
Recommending practical security improvements.
Preparing a professional security assessment report.

This activity simulated the type of work performed by cybersecurity consultants and SOC analysts.

Security Assessment Methodology

I followed a structured five-step approach.

1. Inventory First

The first step was identifying the assets within the network.

Examples include:

Computers
Servers
Network devices
User accounts
Applications
Internet-facing services

Without knowing what exists in a network, it is impossible to protect it effectively.

2. Identify the Risks

After identifying the assets, I looked for possible security risks.

Examples of risks include:

Weak passwords
Unpatched systems
Misconfigured services
Excessive user permissions
Insecure network configurations
Lack of monitoring

The goal was to understand how an attacker might exploit these weaknesses.

3. Prioritize by Risk

Not every vulnerability has the same level of impact.

I learned to prioritize risks based on:

Likelihood of exploitation
Potential business impact
Importance of the affected asset

This helps organizations focus on the most critical issues first.

4. Recommend Specific Fixes

For each identified risk, I suggested practical security improvements.

Examples include:

Enabling Multi-Factor Authentication (MFA)
Applying security updates
Strengthening password policies
Improving network segmentation
Implementing least privilege
Increasing monitoring and logging

Recommendations should always be realistic and actionable.

5. Acknowledge Constraints

Security improvements must consider real-world limitations such as:

Budget
Time
Business operations
Available resources

The best solution is not always the most expensive one—it should also be practical for the organization.

Two Important Mental Models

One of the biggest lessons today was learning to think from two different perspectives.

1. Think Like the Attacker

Ask questions such as:

What weaknesses can I exploit?
Which systems are easiest to compromise?
How could I move through the network?
What valuable information could I target?

Thinking like an attacker helps identify security gaps before criminals do.

2. Think Like the Defender

After identifying weaknesses, the next step is asking:

How can I reduce the risk?
Which controls should I implement?
How can I detect attacks quickly?
How can I limit the impact if a breach occurs?

This mindset focuses on protecting systems and reducing the organization's overall risk.

What I Learned
A structured methodology makes security assessments more effective.
Asset inventory is the foundation of cybersecurity.
Risk should be prioritized based on impact and likelihood.

Key Takeaways

✅ Identify assets before trying to secure them.

✅ Focus on the highest-risk issues first.

✅ Recommend practical security improvements.

✅ Consider business constraints when proposing solutions.

✅ Think like both an attacker and a defender.

✅ Document findings clearly in a professional report.
